# 搜索语法与执行引擎

dowse 在你输入的同时实时执行搜索。查询语法遵循 GitHub 代码搜索语法规范：搜索条件以**文件（File）**为维度进行组合匹配，而非仅局限于单行（Line）。例如，输入 `parse config` 会查找在文件内容任意位置同时包含 `parse` 和 `config` 的所有文件，并分别高亮展示各自命中的代码行。

## 查询语法规则

| 语法形态              | 行为说明                                             | 示例                        |
| --------------------- | ---------------------------------------------------- | --------------------------- |
| `term1 term2`         | 检索同时包含两个词项的文件（词项间隐式为 `AND` 关系）。 | `parse config`              |
| `term1 AND term2`     | 显式 `AND` 逻辑，结合优先级高于 `OR`。                 | `parse AND config`          |
| `term1 OR term2`      | 检索包含任意一个词项的文件。                         | `sqlite OR postgres`        |
| `NOT term` 或 `!term` | 排除包含该词项的文件。                               | `NOT test`、`!mock`         |
| `NOT (a OR b)`        | 支持使用圆括号组合布尔逻辑。                         | `config NOT (test OR mock)` |
| `"exact phrase"`      | 精确短语匹配；内部双引号与反斜杠需使用 `\"` 与 `\\` 转义。 | `"fn main() {"`             |
| `/pattern/`           | 逐行匹配正则表达式。                                 | `/fn \w+_test/`             |
| `content:term`        | 强制将符合限定符格式的文本作为普通正文进行匹配。     | `content:path:foo`          |

> [!NOTE]
> 查询中的正向匹配词会被编译为一个组合正则表达式，用于在展示阶段高亮匹配的代码行。如果一个查询仅由限定符组成（如 `path:*.proto`），dowse 将直接列出所有符合条件的文件，完全无需从磁盘读取文件内容。

## 限定符（Qualifiers）参考

限定符在进入文件正文匹配之前，先对候选文件集合进行快速过滤。包含空格的值可以使用引号包裹（如 `language:"Visual Basic"`），亦可使用正则表达式（如 `path:/src\/(api|web)\//`）。

| 限定符                               | 功能说明                                                  | 示例                                          |
| ------------------------------------ | --------------------------------------------------------- | --------------------------------------------- |
| `path:<glob\|text>`                  | 匹配相对文件路径；若模式中包含 `/`，则默认从仓库根目录开始锚定。 | `path:src/*.rs`、`path:engine`、`path:tests/` |
| `-path:<glob\|text>`                 | 排除路径符合该模式的文件。                                | `-path:tests`、`-path:vendor/`                |
| `language:<lang>` 或 `lang:<lang>`   | 按编程语言名称、常用别名或文件扩展名筛选。                | `language:rust`、`lang:ts`、`lang:python`     |
| `-language:<lang>` 或 `-lang:<lang>` | 排除指定编程语言的文件。                                  | `-lang:md`、`-lang:json`                      |
| `repo:<name>`                        | 将搜索限定在名称包含指定子串的仓库中。                    | `repo:api`、`repo:frontend`                   |
| `-repo:<name>`                       | 排除匹配的仓库。                                          | `-repo:legacy`                                |
| `branch:<name>`                      | 将搜索限定在当前检出分支匹配的仓库中。                    | `branch:main`、`branch:v2`                    |
| `tag:<tag>`                          | 将搜索限定在带有指定标签的仓库中。                        | `tag:mirror`、`tag:owner:alice`               |

## 路径漏斗过滤器

虽然在主搜索框中直接书写 `path:` 限定符足以应对日常需求，但对于层级复杂的代码树，使用独立的**路径漏斗过滤器（Path Filter）**更为直观：

- 按下快捷键 `Ctrl+P`（macOS 为 `Cmd+P`）或点击主搜索框旁边的漏斗图标。
- 输入以空格分隔的多个过滤规则：
  - `src`：保留路径中包含 `src` 的文件。
  - `*.rs` 或 `src/**/*.ts`：按 Glob 通配符匹配路径。
  - `!tests` 或 `-*.md`：排除匹配指定路径的文件。
- 只要当前标签页存在生效的路径过滤规则，该过滤器输入框就会持续保持展开状态。
- 路径过滤条件在磁盘 I/O 之前生效，直接剔除非候选文件。

## 匹配模式与全局开关

搜索框右侧提供了三个全局匹配切换开关：

| 快捷键 (Win / Linux) | 快捷键 (macOS) | 开关名称                     | 功能说明                                                   |
| -------------------- | -------------- | ---------------------------- | ---------------------------------------------------------- |
| `Alt+C`              | `Cmd+Alt+C`    | **区分大小写（Match Case）** | 使所有检索词项区分大小写。默认不区分大小写。               |
| `Alt+W`              | `Cmd+Alt+W`    | **全字匹配（Whole Word）**   | 为词项自动添加词边界标记（`\b`），仅匹配独立的完整标识符。 |
| `Alt+R`              | `Cmd+Alt+R`    | **正则模式（Regex Mode）**   | 将整个输入框的内容视为单条逐行执行的正则表达式。           |

## 划定与收窄检索范围

1. **工作区范围（Workspace Scope）**：在桌面应用中，通过搜索结果上方的范围栏可以按标签组合（如 `owner:alice`、`mirror`）限定检索的仓库集合。详见 [标签与检索范围](app.md#标签与检索范围)。
2. **Facet 细粒度收窄**：左侧边栏（`Ctrl+B`）动态展现当前查询在仓库、分支、语言及一级目录上的命中分布，点击即可快速收窄，且不会改动已保存的工作区配置。
3. **命令行限定**：在终端中使用 `--here`（仅限当前终端所在仓库）、`-t <tag>`（按标签筛选）或 `-W <workspace>`（按工作区文件筛选）。详见 [命令行工具参考](cli.md)。

## 搜索底层执行流水线

每次搜索均遵循高度优化的三阶段并行流水线：

1. **查询编译**：解析查询语句。纯文本词项自动转义正则元字符，全字匹配注入 `\b` 边界。所有正向匹配词汇总为用于展示高亮的组合正则表达式，同时整个表达式树被编译为 [tgrep](indexes.md) 的 Trigram 索引查询计划。
2. **候选集剪枝**：仓库限定符直接剔除不相关的整个代码仓库。针对范围内的每个剩余仓库，Trigram 查询计划在其索引中检索：必选词项求交集，可选词项求并集，否定排除项不参与剪枝。文件监听器所标记的近期变动文件会自动合并进候选集。随后，路径与语言限定符会在不读取文件内容的前提下，提前过滤掉绝大多数非匹配文件。
3. **分块并行验证**：候选文件由 Rayon 线程池按仓库分块并发读取并进行正则校验。各词项按条件短路求值，一旦文件的最终匹配状态已能确定便立即提前返回。当累计找到约 20,000 行（或 10,000 个文件）的匹配结果后，将跳过后续文件的读取，并在摘要中注明结果已截断。

## 性能指标与特征

借助 Trigram 倒排索引的高效候选集剪枝，dowse 过滤掉了 99% 以上无关文件的磁盘 I/O，面对庞大的代码库依然拥有毫秒级响应：

- **索引构建速度**：42,000 个源码文件（约 1.3 GB 源码），初次全量索引构建仅需约 6 秒。
- **交互查询延迟**：常见查询端到端耗时通常保持在 20–60 毫秒之间。
- **毫秒级变更感知**：结合后台文件系统监听器，外部编辑器一旦保存文件，最新改动在数毫秒内即可被检索命中。
