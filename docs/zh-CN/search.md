# 搜索语法与执行引擎

dowse 在你输入的同时实时执行搜索。查询语法全面拥抱 GitHub 代码搜索语法规范：各项条件以**文件（File）**为粒度进行组合，而非以单行（Line）为粒度。例如，输入 `parse config` 会查找在文件内容任意位置同时包含 `parse` 和 `config` 的全部文件，并展示各自命中的代码行。

## 查询语法规则

| 语法形态              | 行为说明                                             | 示例                        |
| --------------------- | ---------------------------------------------------- | --------------------------- |
| `term1 term2`         | 检索同时包含两个词项的文件（词项间隐式包含 `AND`）。 | `parse config`              |
| `term1 AND term2`     | 显式 `AND` 逻辑。优先级高于 `OR`。                   | `parse AND config`          |
| `term1 OR term2`      | 检索包含任意一个词项的文件。                         | `sqlite OR postgres`        |
| `NOT term` 或 `!term` | 排除包含该词项的文件。                               | `NOT test`、`!mock`         |
| `NOT (a OR b)`        | 支持通过小括号组合布尔逻辑。                         | `config NOT (test OR mock)` |
| `"exact phrase"`      | 精确短语匹配；引号内部使用 `\"` 与 `\\` 转义。       | `"fn main() {"`             |
| `/pattern/`           | 逐行匹配正则表达式。                                 | `/fn \w+_test/`             |
| `content:term`        | 将长得像限定符的内容强制作为普通文本处理。           | `content:path:foo`          |

> [!NOTE]
> 查询中的肯定词项会被编译为一个联合正则表达式，用于在展示阶段高亮匹配的代码行。如果一个查询仅由限定符组成（如 `path:*.proto`），dowse 将直接列出所有符合条件的文件，完全无需从磁盘读取文件内容。

## 限定符（Qualifiers）参考

限定符在进入文件正文匹配之前，先对候选文件集合进行快速过滤。包含空格的值可以使用引号包裹（如 `language:"Visual Basic"`），亦可使用正则表达式（如 `path:/src\/(api|web)\//`）。

| 限定符                               | 功能说明                                                  | 示例                                          |
| ------------------------------------ | --------------------------------------------------------- | --------------------------------------------- |
| `path:<glob\|text>`                  | 匹配相对文件路径。若模式包含 `/` 则默认锚定自仓库根目录。 | `path:src/*.rs`、`path:engine`、`path:tests/` |
| `-path:<glob\|text>`                 | 排除路径符合该模式的文件。                                | `-path:tests`、`-path:vendor/`                |
| `language:<lang>` 或 `lang:<lang>`   | 按编程语言名称、标准别名或扩展名筛选。                    | `language:rust`、`lang:ts`、`lang:python`     |
| `-language:<lang>` 或 `-lang:<lang>` | 排除指定编程语言的文件。                                  | `-lang:md`、`-lang:json`                      |
| `repo:<name>`                        | 将搜索限制在名称包含指定子串的仓库中。                    | `repo:api`、`repo:frontend`                   |
| `-repo:<name>`                       | 排除匹配的仓库。                                          | `-repo:legacy`                                |
| `branch:<name>`                      | 将搜索限制在当前检出分支符合条件的仓库中。                | `branch:main`、`branch:v2`                    |
| `tag:<tag>`                          | 将搜索限制在被打上指定标签的仓库中。                      | `tag:mirror`、`tag:owner:alice`               |

## 路径漏斗过滤器

虽然在主搜索框中直接书写 `path:` 限定符足以应对日常需求，但对于层级复杂的代码树，使用独立的**路径漏斗过滤器（Path Filter）**更为直观：

- 按下快捷键 `Ctrl+P`（macOS 为 `Cmd+P`）或点击主搜索框旁边的漏斗图标。
- 输入以空格分隔的多个过滤规则：
  - `src` 保留路径中包含 `src` 的文件。
  - `*.rs` 或 `src/**/*.ts` 执行 Glob 通配匹配。
  - `!tests` 或 `-*.md` 排除指定路径。
- 只要当前标签页存在路径过滤规则，该过滤器输入框就会持续保持展开状态。
- 路径过滤条件在磁盘 I/O 之前生效，直接剔除不合格的候选文件。

## 匹配模式与全局开关

搜索框右侧提供了三个全局匹配切换开关：

| 快捷键 (Win / Linux) | 快捷键 (macOS) | 开关名称                     | 功能说明                                                   |
| -------------------- | -------------- | ---------------------------- | ---------------------------------------------------------- |
| `Alt+C`              | `Cmd+Alt+C`    | **区分大小写（Match Case）** | 使所有检索词项区分大小写。默认不区分大小写。               |
| `Alt+W`              | `Cmd+Alt+W`    | **全字匹配（Whole Word）**   | 为词项自动添加词边界标记（`\b`），仅匹配独立的完整标识符。 |
| `Alt+R`              | `Cmd+Alt+R`    | **正则模式（Regex Mode）**   | 将整个输入框的内容视为单条逐行执行的正则表达式。           |

## 划定与收窄检索范围

1. **工作区范围（Workspace Scope）**：在桌面应用中，通过搜索结果上方的范围栏可以按标签组合（如 `owner:alice`、`mirror`）限定检索的仓库集合。详见 [标签与检索范围](app.md#标签与检索范围)。
2. **Facet 细粒度收窄**：左侧边栏（`Ctrl+B`）动态展现当前查询在仓库、分支、语言及一级目录上的命中分布，单机即可收窄，不影响全局工作区配置。
3. **命令行限定**：在终端中使用 `--here`（仅限当前终端所在仓库）、`-t <tag>`（按标签筛选）或 `-W <workspace>`（按工作区文件筛选）。详见 [命令行工具参考](cli.md)。

## 搜索底层执行流水线

每次搜索均遵循高度优化的三阶段并行流水线：

1. **查询编译**：解析查询语句。纯文本词项自动转义正则元字符，全字匹配注入 `\b` 边界。所有肯定词项汇总为用于匹配行展示的组合正则，同时查询树被编译为 [tgrep](indexes.md) 的 Trigram 索引查询计划。
2. **候选集剪枝**：仓库限定符直接排除整库。对范围内的每一个仓库，Trigram 查询计划快速查询其索引文件：必选词项求交集，可选词项求并集，否定词项不收窄。文件监听器所标记的近期变更文件会被自动并入候选集。随后，路径与语言限定符在不读取文件内容的情况下直接过滤掉绝大部分文件。
3. **分块并行验证**：候选文件由 Rayon 线程池按仓库分块并发读取与正则校验。各词项按需检查，一旦文件整体匹配结果已可判定便立即短路。当找到约 20,000 行（或 10,000 个文件）的匹配结果后，剩余候选文件将跳过读取，并在摘要中注明结果已截断。

## 性能指标与特征

借助 Trigram 倒排索引的高效候选集裁剪，dowse 免去了 99% 以上不必要的文件磁盘读取，在大型代码库中表现尤为卓越：

- **索引构建速度**：42,000 个源码文件（约 1.3 GB 源码），初次索引构建耗时约 6 秒。
- **交互查询延迟**：常见查询端到端耗时通常保持在 20–60 毫秒之间。
- **毫秒级增量保鲜**：结合后台文件系统监听，在外部编辑器保存文件后，修改内容毫秒级即可被检索命中。
